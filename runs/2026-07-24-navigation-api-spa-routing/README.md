## Claim ↔ evidence

Every **firsthand** claim in the post maps to a line in `results.json` / `probe-result.json`
/ `router-check.json`. Claims sourced from external references are listed separately as
*cited, not measured* — the post marks them the same way.

### Firsthand (measured on Chromium 147.0.7727.15 + Firefox 148.0.2 + WebKit 26.4)

| Claim in the post | Evidence | Value |
|---|---|---|
| Of 11 navigation triggers, the **History API observes only 2** (fragment + same-document Back); the **Navigation API observes all 11** | `results.json` → `observation_matrix` · `probe-result.json` → `engines[].triggers` | 2 / 11 vs 11 / 11 |
| `popstate` does **not** fire on `pushState`/`replaceState`, programmatic nav, link click, GET form, or `location.assign()` | `probe-result.json` → `engines[].triggers` | popstate = 0 on those |
| Cross-origin and download navigations report **`canIntercept=false`** (download exposes `downloadRequest`) | `results.json` → `observation_matrix.canIntercept_false_cases` | verified |
| History API exposes only `history.length` (a single int, engines even **disagree**: 5 vs 4); Navigation API returns the **full URL array + current index** | `results.json` → `stack_visibility` · `probe-result.json` → `engines[].stack_after_3_pushes` | verified |
| A `navigate` + `intercept()` handler renders a view and updates the URL with **zero framework** (`full_page_reload_avoided=true`) | `results.json` → `spa_intercept_verified` · `probe-result.json` → `engines[].spa_intercept` | verified (chromium, firefox) |
| Shipped **react-router 8.3.0** and **@tanstack/history 1.162.0** reference the Navigation API **0 times** and still use `popstate` | `router-check.json` | 0 hits, popstate present |
| Playwright **WebKit 26.4 exposes no `window.navigation` at all** | `results.json` → `webkit_absence` · `probe-result.json` → webkit `surface` | verified — see caveat below |

### Cited, not measured (honestly flagged in the post too)

| Claim | Source |

| Navigation API reached Baseline "newly available" in January 2026 | web.dev / MDN Baseline |

### Explicitly NOT verified — the WebKit ≠ Safari split matters here

Playwright's **WebKit is not Safari.** In the WebKit 26.4 build, `window.navigation` is absent,
so the `navigate` event never fired there. But caniuse lists **Safari 26.2+ as supporting** the
API, and we did **not** measure real Safari. The WebKit result is a genuine observation about
the *Playwright E2E environment* (a Navigation-API router silently falls back there), never a
verdict on Safari. This is stated plainly in both the post and `results.json.webkit_absence`.

Also not measured: real user browsers (extensions/bfcache/restored sessions), scroll/focus
restoration, `intercept()` precommit/commit options, POST forms, and `traverseTo()` in real use.
The router grep covers **published dist only** — not unreleased branches or open PRs.

## Environment

Windows 11 x64 · Playwright 1.59.0 (Python 3.11.9), headless · Chromium **147.0.7727.15** /
Firefox **148.0.2** / WebKit **26.4**. Two throwaway localhost origins (127.0.0.1 vs localhost
on different ports) make cross-origin behavior real, not simulated. Hardware is irrelevant —
this observes which events fire, not how fast.
